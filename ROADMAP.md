## M3 - Hardening and release

- [x] Incremental rebuilds: transforms memoized on content hashes, write-if-changed, pruning with
preserved paths
- [ ] Dependency-driven partial rebuilds (only re-render pages affected by a change)
- [x] Perf: 301 pages of markdown build in 490 ms, watch round-trip 83 ms (target was 1 s and
      100 ms). This repository's own site is 251 pages in ~5.2 s, of which 1.5 s is the compiler
      reading the eighteen assemblies its reference is written from; its watch round-trip is
      43-69 ms, because none of that is redone when a page changes
- [x] `nacara check` (link and anchor integrity), CI gate
- [x] Plugin author documentation, `dotnet new` template (`nacara-docs`)
- [x] Packaging: all nineteen packages pack with docs, README and correct dependencies
- [x] Release workflow: EasyBuild.ShipIt opens a changelog pull request after a green build on
      `v3`, and merging it writes the `chore: release …` commit that publishes
- [ ] Publish the first beta to NuGet (a decision, not a task)

## Waiting on a decision, not on work

- [ ] **Publish the first beta**: everything packs, the release workflow is written and every
      changelog carries the `force_version` it needs - `Nacara.Core` at `2.0.0-beta.1`, continuing
      the line already on NuGet, and `1.0.0-beta.1` for the eighteen packages that are new. What
      is left is merging the changelog pull request ShipIt opens, and then removing those lines.
- [ ] **Deploy the documentation**: it builds as it would deploy (`/Nacara/`, with an origin), but
      `master` currently owns the published site.
- [ ] **Publishing a wasm-capable tree-sitter core**: built per platform by
      `.github/workflows/native-runtimes.yml`, on that platform, and published to npm as
      `@nacara/tree-sitter-runtime-<rid>` by running it with `publish` ticked - about 8 MB, of
      which a site fetches one. Nothing is published yet and the `@nacara` scope does not exist,
      so `Nacara.Plugin.Highlight.TreeSitter` currently works only where
      `./build.sh tree-sitter runtime` has put the natives beside the build. That package is
      unusable off this repository until this is done. They are versioned by tree-sitter rather
      than by any package here, so they are published when tree-sitter moves and never in step
      with a release.
- [x] **Live examples via the Fable in-browser compiler** (`Nacara.Plugin.LiveExample`): a block
      marked `live` stays static until Run, then compiles in a worker and runs in a sandboxed
      frame, with the result in Result/Console/JavaScript tabs. CodeMirror hosts hover, completion
      and error markers off the same worker; a library reaches a snippet as a named preset. Scoped
      in [`notes/live-examples.md`](notes/live-examples.md), prototyped in
      [`prototypes/live-example/`](prototypes/live-example/). Pinned to
      `@fable-org/fable-standalone` 3.1.0, which publishes the Fable it was built from - so the
      build fetches that same Fable with `dnx` to precompile a library, and nothing has to be
      installed for the two to agree. See
      [`notes/fable-standalone-precompiled/`](notes/fable-standalone-precompiled/).

## M4+ - Differentiators

- [x] API reference (`Nacara.Plugin.FSharpApi`): rewritten against the content model, not vendored.
      Reads assemblies through the F# compiler; a page per type or module, members as entries that
      open, declarations written out, several assemblies read in one pass and merged by namespace
- [x] Link validation (`Nacara.Plugin.LinkValidator`): every link the site published, anchors included, with
      external checks and a cache
- [x] tree-sitter backend (`Nacara.Plugin.Highlight.TreeSitter`): grammars as wasm, the grammar's
      own queries, predicates evaluated, same token classes as TextMate
- [x] Versioning plugin: `versions.json`, switcher, outdated-version notice
- [x] Canonical URLs and social metadata, from `Site.origin`
- [x] Sitemap plugin, with `hreflang` cross-references
- [x] Assets, one tool per format and none of them overlapping: Lightning CSS bundles and minifies
      the stylesheets, esbuild bundles and minifies the scripts, NUglify minifies the HTML
- [x] Markdown linting (`Nacara.Plugin.Linter.Rumdl`): rumdl over the site's own sources, its
      findings reported as diagnostics like any other
- [x] i18n: locale picker paired by translation key
- [x] i18n fallback: an untranslated page is published in every locale carrying its original
      content and saying so, on unless `Site.fallBackToDefaultLocale false` turns it off
- [ ] i18n workflows: translation status
- [x] Literate F# / `.fsx` pages
- [x] Live examples via the Fable in-browser compiler
