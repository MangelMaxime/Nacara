    A site with its own look

    This page builds a small blog without a theme: a home page, an about page, posts, a page per tag, an Atom feed and a 404 page. The layouts and the stylesheet are yours. The engine and Theme.Core bring the rest.

    Create the project

    The project holds three F# files, in this order in the .fsproj:

    • Blog.fsproj
    • Posts.fs
    • Layouts.fs
    • Site.fs
    • assets/
      • site.css
    • content/
      • pages/
        • index.md
        • about.md
        • 404.md
      • posts/
        • hello.md

    Posts

    Posts.fs holds the front matter of a post, the collection, the tag pages and the feed.

    Collection.create "posts" reads the files of content/posts.

    Collection.draft names the posts that are drafts. A draft is published by watch and left out of build, including from the tag pages and the feed.

    The collection has no layout yet: Site.fs adds it. The layouts can then read the collection.

    Tag pages

    A tag page lists the posts filed under one tag, ten per page.

    TypedPage<Post> is a page and its decoded front matter.

    Taxonomy.group groups the posts by tag. It returns one Term per tag, with its Name, its Slug and its Items. A post with several tags is in each of them. Tags with the same slug are one term. Terms are ordered by name, ignoring case.

    Paging.split splits a list into Paged values. Paging.route gives /tags/fsharp/ for page 1 and /tags/fsharp/page/2/ for page 2. See Paging.

    Feed

    See the feed plugin.

    Layouts

    A layout is a function from a PageContext<'FrontMatter> to markup. Layouts.fs holds a shell shared by every page, and one layout per kind of page.

    The shell

    FunctionWhat it renders
    Head.ofContext title description contextCharset, viewport, title, description, canonical url, social cards
    Behaviours.bootstrapTag ()The script that sets the colour scheme before the first paint
    Feed.headLink site feedThe <link rel="alternate"> of the feed
    Shell.stylesheetLinks siteA link to every stylesheet: the plugins' and the site's
    Shell.skipLink className targetThe link that jumps past the navigation
    Behaviours.scriptTag siteThe shared script
    Shell.scripts siteEvery script plugins contributed, and the site's

    context.LinkTo takes the source path of a page, relative to its collection root, and returns its url. A path starting with / is put under the base url. A path that names no page is reported by the link validator.

    A button with data-nacara-theme-pick picks a colour scheme. The shared script sets aria-pressed on the button picked. See the attributes it reads.

    Posts and tag pages

    context.Content is the page's rendered body. Paging.slots lists the pages of a pager, with a Gap for the pages left out.

    Pages

    The pages that are not posts name their layout in their front matter.

    context.PagesOf collection returns the pages of a collection in the page's locale, as TypedPage values.

    The site

    Collection.layouts renders each page with the layout its front matter names. A page naming another layout fails the build.

    Collection.fromPages makes a collection from the pages of another. Each value the function returns is the front matter of one page. The pages have no source file, so the collection needs a Collection.route.

    content/pages/404.md is written as 404.html, where static hosts look for it.

    Styles

    ThemeCore.register registers the shared script, the default --nacara-* tokens and the stylesheet that draws what plugins emit: code blocks, callouts, tabs. They are in the nacara.tokens and nacara.content cascade layers. The site's own stylesheet is outside the layers, so its rules win over them.

    The tokens are set on :root, :root[data-theme="light"] and :root[data-theme="dark"]. To change one, set it under the same selector. A site that defines every token itself turns the default ones off:

    The tokens lists them.
