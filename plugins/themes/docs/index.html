    Theme.Docs

    Nacara.Theme.Docs is what a documentation theme is built from: the vocabulary a site configures a theme with, and the models of its navbar, sidebar, table of contents and page navigation. It is built on Theme.Core.

    Nacara.Theme.Default is built on it. A documentation theme of your own is built on it the same way.

    Add it

    What a theme is

    A theme is a plugin and a layout. The plugin registers the theme's assets and what Theme.Docs needs of the site. The layout is a function from PageContext<'FrontMatter> to markup, given to a collection.

    A site uses it the way it uses the default theme:

    Vocabulary

    The namespace Nacara.Theme holds what a site writes in its options, whichever theme draws it.

    TypeWhat it is
    NavbarItemAn entry of the navbar: a link, a section, a dropdown, an icon, a widget
    MenuItem, MenuAn entry of a sidebar menu, and the functions that build one
    DocsOptionsThe navbar, the menus, the edit url and the menu limits
    DocPageWhat a theme needs to know about the page it renders
    DocFrontMatterThe front matter of a documentation page, and its decoder

    DocsOptions

    The part of a theme's options every documentation theme shares. A theme holds one in its own options record and adds its own fields beside it.

    FieldTypeDefault
    NavbarNavbarItem list[]
    NavbarEndNavbarItem list[]
    MenusMap<string, MenuItem list>Map.empty
    EditUrlBasestring optionNone
    MenuLimitint500
    MenuGroupLimitint150

    DocsOptions.navbar, navbarEnd, menu, menus, editUrl, menuLimit and menuGroupLimit set them.

    Models and resolvers

    A resolver reads the options and the page and returns a model. A model holds every url resolved and every state settled, and no markup. The theme renders it.

    Every resolver takes a PageScope.

    ResolverModelWhat it holds
    Navbar.resolve options scopeNavbarModelThe brand, the entries at each end of the bar, the current section
    Sidebar.resolve options doc scopeSidebarModelThe section's menu as a tree, the trail to the page open, the filter box, the drawer
    Toc.resolve doc scopeTocModel optionThe page's headings. None when the page shows none
    PageNav.resolve options scopePageNavModel optionThe previous and next pages of the section
    EditLink.resolve options scopeEditLinkModel optionWhere the page is edited at its source

    A section's menu comes from Sidebar.menuOf: the menu the site declared, else the one a plugin offered, else None. With None, Sidebar.resolve lists the section's pages in front-matter order. SidebarModel.Source says which it was.

    PageNav.among site ordered page gives the previous and next of any ordered list of pages.

    Registration

    ThemeDocs.configure registers what every documentation theme needs of the site: what ThemeCore.configureBase registers, the menus written whole for the filter box, and the 404 page.

    ThemeRegistration

    FieldTypeWhat it is
    OriginstringThe theme's name. A page the theme generates says this generated it
    DocsDocsOptionsThe menus, read to write the pruned ones whole
    NotFound(PageContext<DocFrontMatter> -> ReactElement) optionThe layout the 404 page is rendered with. None writes none

    Front matter and layouts

    Docs.collection name layout is a collection reading DocFrontMatter, with the title, the order and the table of contents wired.

    DocPage.Layout names the layout a page asked for: doc, bare, splash, or one the theme knows. DocFrontMatter.layouts maps bare and splash to what they do to a DocPage.

    A theme with layouts of its own adds to that map and reads front matter with DocFrontMatter.decoderWith, which fails the build on a layout it was not given:

    A collection with a front-matter type of its own maps it onto a DocPage and calls the shell.

    The menu script

    nacara-menu.js is registered by ThemeDocs.configure and written by Shell.scripts. It reads nothing but data-nacara-menu-* attributes.

    AttributeOnBehaviour
    data-nacara-menu-groupA <details> of the menuIts fold is remembered from page to page
    data-nacara-menu-memory="false"The sidebarThe folds are not remembered
    data-nacara-menu-filterAn <input>Filters the menu
    data-nacara-menu-sourceThe same inputWhere the section's whole menu is, when the page holds a part of it
    data-nacara-menu-listThe menu's top-level <ul>Where the rest of a pruned menu is grafted
    data-nacara-menu-leaf-template, data-nacara-menu-group-templateA <template> in the sidebarThe markup grafted entries are cloned from

    The template for a leaf holds one <li> with an <a>; the one for a group holds an <li> with a <details>, a <summary> holding an <a>, and a <ul>. The script sets the link's href and text, the group's data-nacara-menu-group, and appends children to the <ul>.

    data-nacara-menu-source names one of the menus ThemeDocs.configure writes whole, under assets/menu.
