    type Collection<'FrontMatter> =
    {
        Name: string
        Source: ContentSource
        Decoder: Decoder<'FrontMatter>
        TitleOf: 'FrontMatter -> string
        OrderOf: 'FrontMatter -> int
        TocOf: 'FrontMatter -> TocRange option
        RouteOf: PageInfo<'FrontMatter> -> Route
        Layout: PageContext<'FrontMatter> -> ReactElement
        DraftOf: 'FrontMatter -> bool
    }
    AssemblyNacara.Core

    A collection of content sharing a front-matter type, a route shape and a layout.

    Fields

    Name: string
    Source: ContentSource
    Decoder: Decoder<'FrontMatter>
    TitleOf: 'FrontMatter -> string
    OrderOf: 'FrontMatter -> int
    TocOf: 'FrontMatter -> TocRange option

    The heading levels this collection's pages put in their table of contents, when they say.

    Published only while serving.

    Functions and values

    build<'FrontMatter> (collection: Collection<'FrontMatter>) : CollectionDefinition

    Erase the front-matter type, capturing the typed functions in closures.

    create<'FrontMatter> (name: string) (decoder: Decoder<'FrontMatter>) : Collection<'FrontMatter>

    Start describing a collection. The decoder is what gives its front matter a type.

    Parameter
    nameWhat you call the collection. Its files are read from content/<name>, in every format your plugins read. sourceAll reads another directory.
    decoderReads the front matter of every page, and fails the build with a file and a line when a page does not match.

    Returns. A collection with the defaults of every field, ready to point somewhere.

    defaultRoute<'FrontMatter> (info: PageInfo<'FrontMatter>) : Route

    Route a page from its path: guide/index.md becomes /guide/.

    A 404 page at the root of the collection is published at 404.html, with notFound.

    derive<'FrontMatter> (name: string) (from: string list) (derive: DerivedContext -> GeneratedContent list) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Generate this collection's pages from the pages of other collections.

    Runs once the collections it names are loaded, with their pages in hand: front matter decoded, bodies not yet rendered. The pages it returns then go through routing, rendering and link checking as any file would, and watch mode rebuilds them when a page they were derived from changes.

    Parameter
    nameWhat generated the pages, for diagnostics.
    fromThe collections whose pages it reads. A collection may derive from another derived one, as long as nothing goes round in a circle.
    deriveCalled once per build with those pages, and returns the pages to publish.
    collectionThe collection being described.
    draft<'FrontMatter> (isDraft: 'FrontMatter -> bool) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Pages that are published while serving, and left out of a build.

    A draft is left out before any collection derives from it, so it is in no index and no feed of a build.

    Parameter
    isDraftGiven the decoded front matter, whether the page is a draft.
    collectionThe collection being described.
    fromPages<'Source, 'FrontMatter> (name: string) (source: Collection<'Source>) (make: TypedPage<'Source> list -> 'FrontMatter list) : Collection<'FrontMatter>

    Start describing a collection whose pages are made from the pages of another.

    Each value make returns is the front matter of one page, with no body. Give the collection a route: the pages have no path of their own. They are in the root locale.

    Parameter
    nameWhat you call the collection.
    sourceThe collection whose pages it is made from.
    makeGiven the pages of source, front matter decoded and bodies not yet rendered, the front matter of each page to publish.
    generated<'FrontMatter> (name: string) : Collection<'FrontMatter>

    Start describing a collection whose pages are generated with their front matter as a value.

    Its pages come from producer or derive, each made with ofValue. Content that carries front matter as text fails the build.

    Parameter
    nameWhat you call the collection.
    layout<'FrontMatter> (layout: PageContext<'FrontMatter> -> ReactElement) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    How pages of this collection are rendered.

    Parameter
    layoutGiven the page and the site around it, the markup of the whole document. A theme's layout is a function of exactly this shape.
    collectionThe collection being described.
    layouts<'FrontMatter> (layoutOf: 'FrontMatter -> string) (layouts: (string * (PageContext<'FrontMatter> -> ReactElement)) list) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Render each page with the layout its front matter names.

    A page naming a layout that is not in the list fails the build with nacara/front-matter-invalid. Call it after the collection's decoder is set.

    Parameter
    layoutOfGiven the decoded front matter, the name of the layout to use.
    layoutsEach layout, by the name a page uses for it.
    collectionThe collection being described.
    order<'FrontMatter> (orderOf: 'FrontMatter -> int) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    How pages of this collection are ordered in menus and index pages.

    Parameter
    orderOfGiven the decoded front matter, a number to sort by. Pages sharing a number fall back to their title.
    collectionThe collection being described.
    pagesOf<'FrontMatter> (collection: Collection<'FrontMatter>) (pages: Page list) : TypedPage<'FrontMatter> list

    The pages of a collection among pages, with their front matter typed.

    Parameter
    collectionThe collection to read.
    pagesThe pages to look through: a layout's context.Pages, a hook's or a derived collection's.
    producer<'FrontMatter> (name: string) (produce: ProducerContext -> GeneratedContent list) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Generate content instead of reading it from disk.

    Parameter
    nameWhat to call the producer. Diagnostics use it to say where a generated page came from.
    produceCalled once per build, with what the build knows so far, and returns the pages to publish. They go through routing, rendering, search and link checking exactly as a file would.
    collectionThe collection being described.
    route<'FrontMatter> (routeOf: PageInfo<'FrontMatter> -> Route) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Where pages of this collection live in the site.

    Parameter
    routeOfGiven a page and what is known about it, the route to publish it at. Two pages returning the same route fail the build with nacara/duplicate-route.
    collectionThe collection being described.
    routePrefix<'FrontMatter> (prefix: string) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Prefix every route of the collection with a path.

    Parameter
    prefixSegments to put in front of every route, like "reference" or "blog/posts". Each one is slugged, and empty ones are dropped.
    collectionThe collection being described.
    source<'FrontMatter> (root: string) (patterns: string list) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Read content from files under root.

    Use this only when you want something narrower than "every format this site reads"

    • a directory holding samples beside its pages, say. Left alone, a collection reads every file a format plugin claims, so registering literate F# is all it takes to publish an .fsx.
    Parameter
    rootA directory, relative to the content directory.
    patternsGlobs of what to read from it, like [ "**/*.md" ]. A path matching none of them is not part of this collection.
    collectionThe collection being described.
    sourceAll<'FrontMatter> (root: string) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Read every file under root whose format a plugin reads.

    Parameter
    rootA directory, relative to the content directory.
    collectionThe collection being described.
    title<'FrontMatter> (titleOf: 'FrontMatter -> string) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    How to read a page's title out of its front matter.

    Parameter
    titleOfGiven the decoded front matter, the page's title - its heading, its menu entry and its <title>.
    collectionThe collection being described.
    toc<'FrontMatter> (tocOf: 'FrontMatter -> TocRange option) (collection: Collection<'FrontMatter>) : Collection<'FrontMatter>

    Which heading levels a page puts in its table of contents.

    This is read from the front matter, like the title, so a page can carry its own answer: Collection.toc _.Toc with a TocRange option field. Return None to leave the markdown plugin's option in charge.

    Parameter
    tocOfGiven the decoded front matter, the heading levels this page lists, or None to leave the decision to the markdown plugin.
    collectionThe collection being described.
