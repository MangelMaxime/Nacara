Site

type Site =
    {
        Title: string
        Description: string option
        BaseUrl: string
        Origin: string option
        VersionPrefix: string option
        Locales: Locale list
        FallBackToDefaultLocale: bool
        OutputDirectory: string
        StaticDirectory: string option
        Stylesheets: string list
        Scripts: string list
        Plugins: IPlugin list
        Collections: CollectionDefinition list
    }
AssemblyNacara.Core

A site, described as a value.

You build it with a plain pipeline - Site.create … |> Site.baseUrl … |> Site.plugin … - so your configuration is an ordinary value: share it between builds, reuse it in tests, and let the compiler tell you when it is wrong.

Fields

Title: string
Description: string option
BaseUrl: string
Origin: string option

Absolute origin the site is published at, for example https://example.com. Needed by anything that must produce a full URL: canonical links, sitemaps, feeds.

VersionPrefix: string option

Set when this build is one version among several deployed side by side.

Locales: Locale list
FallBackToDefaultLocale: bool

Generate a page in the default locale's content for locales that have no translation of it yet, rather than leaving a hole in the site.

OutputDirectory: string

Directory receiving the built site, relative to the project root.

StaticDirectory: string option

Directory copied verbatim into the output, relative to the project root.

Stylesheets: string list

Stylesheets of your own, linked on every page. Paths are relative to the project root.

Scripts: string list

Scripts of your own, loaded on every page. Paths are relative to the project root.

Plugins: IPlugin list
Collections: CollectionDefinition list

Functions and values

baseUrl (value: string) (site: Site) : Site

The path the site is served from.

Parameter
valueA path with slashes at both ends: / at a domain root, /MyLibrary/ under a project page. Every link the build emits goes through it, so you can move a site without editing a single page.
siteThe site being described.
collection<'FrontMatter> (value: Collection<'FrontMatter>) (site: Site) : Site

Add a typed collection. Its front-matter type is erased here and nowhere else.

Parameter
valueA collection: where its content comes from, how its front matter is decoded, where its pages are routed, and what renders them.
siteThe site being described.
create (title: string) : Site

A site with the defaults of every field, ready to be described.

Parameter
titleWhat your site is called. It becomes the <title>, the brand in the navbar, and the site a search result says a page belongs to.
description (value: string) (site: Site) : Site

What your site is about, for pages that have nothing better to say.

Parameter
valueOne sentence. It becomes the meta description of any page whose front matter carries none of its own.
siteThe site being described.
fallBackToDefaultLocale (value: bool) (site: Site) : Site

Whether a locale with no translation of a page still gets that page.

On by default. A half-translated site should still be usable in either language, so an untranslated page shows its original content and says so, rather than 404ing or vanishing from the menu.

Parameter
valuetrue to publish every page in every locale, translated or not; false to publish a page only in the locales that have it.
siteThe site being described.
locales (values: Locale list) (site: Site) : Site

Locales of the site. Exactly one must be the root locale.

Parameter
valuesThe languages the site is written in. The root one is served from the base URL, the rest from a prefix of their code - see root and other.
siteThe site being described.
noStaticFiles (site: Site) : Site

Copy no directory as it is: every file your site publishes is produced.

origin (value: string) (site: Site) : Site

Where the site is published, for the URLs that have to be absolute.

Canonical links, sitemaps and social cards all need a full URL, and only you know where the site is deployed. Leave this out and they are left out too, rather than guessed at.

Parameter
valueThe scheme and host you deploy under, with no trailing slash: https://example.github.io.
siteThe site being described.
output (value: string) (site: Site) : Site

Where the built site is written.

Parameter
valueA directory, relative to the project root. The build removes whatever it no longer produces, so do not keep anything of your own in there.
siteThe site being described.
plugin (value: IPlugin) (site: Site) : Site

Add a plugin, which registers what it contributes when the build starts.

Parameter
valueThe plugin. Plugins register in the order you add them, and that order decides the order of anything running in a sequence - transforms, hooks, assets.
siteThe site being described.
rootLocale (site: Site) : Locale

The root locale, or the first one when none was marked as root.

Parameter
siteThe site being described.
script (path: string) (site: Site) : Site

A script of your own, loaded on every page.

Loaded as a classic script, so an import in it needs a bundler registered - unlike a stylesheet, whose imports a browser would resolve on its own.

Parameter
pathThe script, relative to the project root.
siteThe site being described.
staticFiles (value: string) (site: Site) : Site

A directory copied into the output as it is.

Parameter
valueRelative to the project root. Its contents land at the root of your site, so static/logo.svg is served as /logo.svg.
siteThe site being described.
stylesheet (path: string) (site: Site) : Site

A stylesheet of your own, linked on every page after the theme's.

Bundled and minified like any other, so it may @import its neighbours - every stylesheet beside it is given to the bundler. Files under StaticDirectory are copied untouched instead.

Parameter
pathThe stylesheet, relative to the project root.
siteThe site being described.
toInfo (site: Site) : SiteInfo

The read-only view handed to layouts and plugins.

validate (site: Site) : Diagnostic list

Configuration problems worth refusing to build over.

version (prefix: string) (site: Site) : Site

Deploy this build under a version prefix, alongside other versions.

Parameter
prefixWhat this build is called in a URL, like v2 or next. It becomes the first segment of every route the build writes.
siteThe site being described.
